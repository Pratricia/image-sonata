## 一句话结论（先看这个）

**模型解决的是"波形从哪来"，我们解决的是"结构从哪来"。** 这两件事不冲突，但也不能互相替代：

- 想直接得到"能听的成品歌"→ 用 ACE-Step / Stable Audio / Suno 这类模型，代价是 GPU、几十秒到几分钟的推理、以及不可控（同一张图每次都不一样）。
- 想"一张图 → 一段结构完整、可复现、可解释的音乐"→ 我们现在的规则引擎才是对的路子，模型最多只能当**音源**用（把 MIDI/事件渲染成更好听的音色）。
- **最值得抄的不是生成模型，是"乐理库 + 人声合成器"**：前者能省掉手写音阶/和弦的活，后者能把"电子琴味的人声"换成"像嗓子的声音"。

给本项目的落地优先级（按性价比排序）：

1. ~~**借 Hymmnos 的音位学**（`03-hymmnos.md`）——零依赖，只改音节生成规则~~ ✅ **已落地**：`deriveVoxMood()` + `HYMN_*` 音节库 + `CONS_SPEC` 辅音分档，六张示例的想音互不相同。
2. **Tonal.js**（`02`）——40KB 单文件，可替换 `util.js` 里手写的音阶/和弦换算。
3. **Pink Trombone / WORLD 式声道模型**（`02`）——真正解决"不像人声"，但要处理许可证。
4. **生成模型后端**——不放进主路径，最多做"参考音源"，因为它破坏"同图同声"和"零依赖"。
