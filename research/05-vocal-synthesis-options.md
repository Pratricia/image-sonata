# 人声合成：已有方案盘点（v4）

> 起因：`voxV()` 用"周期性波表 + 字头噪声"，听起来像风琴在发"啊、啊、啊"。
> 这一页把"别人怎么解决的"按**能不能塞进本项目**分成三档，并给出建议。
>
> 本项目的硬约束：零依赖、无构建、`file://` 双击可跑、不联网、同图同声（确定性）。
> 这三条约束直接砍掉了整个"神经网络"档。

---

## 一、三档方案

### 第 1 档：神经网络 SVS（质量最高，但进不来）

| 项目 | 许可 | 形态 | 为什么进不来 |
|---|---|---|---|
| **NNSVS** | MIT | Python + PyTorch | 需要训练好的模型 + 推理运行时；MOS 3.86（作者自测），是目前开源天花板 |
| **DiffSinger** | MIT / OpenVPI 分支 Apache-2.0 | PyTorch，扩散模型 | 模型体积上百 MB，需要 GPU/CPU 推理框架 |
| **Sinsy** | Modified BSD | C++，HMM 开源、DNN 闭源 | 开源版停留在 2015 年的 HMM，音质已被超过 |
| **OddVoices** | Apache-2.0，内置音色**公有领域** | C++17 → **WASM**，浏览器能跑 | 是拼接式（下一档），不是神经网络；但 WASM 版是一坨二进制 + 打包流程，违反"无构建" |

**结论**：这一档只能当"构建期工具"——在开发机上离线跑一次，把结果做成音库（见第 3 档）。

### 第 2 档：程序化合成（能裸 JS 跑，但天花板是"合成人声"）

| 方案 | 许可 | 原理 | 音质天花板 |
|---|---|---|---|
| **Pink Trombone** | **MIT**（Neil Thapen, 2017） | 44 段 Kelly-Lochbaum 数字波导（真·声管）+ LF 声门源 + 鼻支管 + 摩擦湍流 + 爆破瞬态 | 学术界评价"convincingly mimics human vocal sounds"，但一听就知道是合成的 |
| **klattsch** | MIT | Rosenberg 声门脉冲 + 3 路并联共振峰 biquad，AudioWorklet / 纯 JS | 作者自述 **"late-70s/early-80s tier (Votrax, SAM)"** |
| **chdh/klatt-syn** | MIT | Klatt 1980 cascade/parallel 参考实现，TypeScript | 同上，教科书级语音，不是歌声 |
| **Qlatt** | MIT | Klatt + WASM 音素前端 | 同上 |
| **eSpeak-NG** | GPL-3.0 | 共振峰；有唱歌补丁（PR #749），靠外部 UTAU/MBROLA 后端变调 | GPL 传染 + 官方自称"不如大型合成器自然" |

**关键差别**：Klatt 那一系是**静态共振峰 + 参数包络**，本质上还是"滤波器"，只是比我们的波表多了几个峰；
Pink Trombone 是**逐采样的物理波导**，元音之间可以连续滑（舌头真的在动）、辅音是"收紧管子 + 湍流噪声 + 爆破"，
所以它听起来会说话，而不是在发元音。

**Pink Trombone 的控制参数（可直接当我们的映射目标）**：

| 参数 | 范围 | 用途 |
|---|---|---|
| `frequency` | 75–400 Hz | 音高（我们的 `midi`） |
| `tenseness` | 0–1 | 紧/松：0 气声、1 紧绷（对应"想音"力度） |
| `tongue.index` / `tongue.diameter` | 12–29 / 2.05–3.5 | 元音（a/i/u/e/o 各一组值） |
| `constriction.index` / `diameter` | 2–44 / 0–3 | 辅音：<0.3 出湍流、=0 全闭塞（爆破） |
| `lip.diameter` | 0–1.5 | 圆唇（o/u） |
| `velum` | 0–0.4 | 鼻音 m/n |
| 声道长度 | 男 44 段 / 女 36–38 段 | 音色性别 |

女性声道参数来自 Cámara et al. 2025（EURASIP JASMP）：长度 16 cm → 14 cm、口腔段数 44 → 38。

### 第 3 档：采样拼接 + PSOLA（最像人，但要有音库）

| 项目 | 许可 | 说明 |
|---|---|---|
| **OddVoices** | Apache-2.0，内置三个音色**公有领域** | diphone 拼接 + MBR-PSOLA，专为唱歌设计，WASM 版可在浏览器跑 |
| `@audio/shift` | MIT | 15 种变调算法，含 `psola` / `formant` / `lpc`，纯 JS |
| `audiojs/stretch` | MIT | PSOLA / WSOLA 时间伸缩 |
| SoundTouchJS | MPL-2.0 | 变调 + 变速，有 formant correction |

音源（法律上能用的）：

- **PJS**（phoneme-balanced Japanese singing voice，CC BY-SA 4.0）：100 首带音素标注的唱段；
- GTSinger：免费但研究许可；VocalSet 等：研究许可；
- **CC0 / 公有领域的"唱出来的元音"极少**——大部分是朗读语料。

代价：几十到上百个采样（1–3 MB）、要做 GCI 对齐 / 相位补偿 / 音量归一化
（OddVoices 的 dev log 里踩过的坑：MBR 相位、per-phoneme 音量匹配、破碎感）。

## 二、为什么"滤波器组"这条路本项目已经试过并且失败了

v2 用过"3 路并联 bandpass 共振峰滤波器组"，两个后果：

1. 离线渲染从 36 s 涨到 180 s（每个音节 6 个滤波器 × 600+ 音节）；
2. 音质并没有变好——因为共振峰频率在**事件内是静止的**，等于把一个静态元音切成很多段。

→ 单纯的 BiquadFilter 堆叠不是答案。要有"会动的声道"，要么物理模型（第 2 档），要么真采样（第 3 档）。

## 三、建议

### 推荐：第 2 档的 Pink Trombone（MIT）

理由：

1. 它修的是**根因**：现在的问题是"共振峰不动 + 声门源是锯齿"，PT 是"管子会变形 + LF 声门源"；
2. MIT，纯 JS，无 AudioWorklet、无 WASM、无网络 → `file://` 双击仍然能跑；
3. 它跑在 **JS 循环里**，输出一段 buffer，正好躲开"每个音符一堆 Web Audio 节点"的渲染爆炸；
4. 确定性的：噪声用 `mulberry32(seed)` 喂，同图同声不受影响。

实现轮廓：

```
score.js 已有的 {t, midi, dur, syl:[{u,d,m,v,cons}]}
        ↓  映射成参数时间线
        {time, f0, tongueIndex, tongueDiam, lipDiam, constriction, velum, tenseness}
        ↓  src/js/voxmodel.js（纯 JS，逐采样）
        Float32Array（单声道，整首人声）
        ↓  AudioBufferSourceNode
        混音 / 导出
```

- 元音 → 舌头位置表（5–8 个元音各一组 index/diameter）；
- 辅音 → 收紧管子 + 噪声（s/sh/f）或全闭塞 + 释放瞬态（p/t/k/d/b/g）；
- 想音（`mood`）→ `tenseness` + 颤音深度 + 气声量；
- 段与段之间舌头参数用 40–80 ms 滑动 → 这就是"口型渐变"，也是现在最缺的东西。

风险（先说清楚）：

- **它不是歌手**。会是"一个很像人的合成嗓音"，好过现在的风琴，但不要指望 Vocaloid 水准；
- 渲染开销要实测（PT 原本是在 ScriptProcessor 里实时跑的，离线整首大概几秒到十几秒）；
- 需要一个"正在准备人声"的短暂状态（可以先播伴奏、人声迟到 1–2 秒，或者预渲染）。

### 备选 A：第 3 档，预渲染音库

能到"接近真人"，但要引入 1–3 MB 音频资源 + PSOLA 实现 + 一次性离线制作流程，
并且要解决"音库从哪来"（PJS 是 CC BY-SA，会传染到音频素材）。

### 备选 B：不假装独唱

做成"人声合唱铺底"（多声部失谐 + 强混响 + 只唱元音），不做辅音。
成本最低、风险最小，但用户要的"塔语歌曲感"就没有了。

## 四点五、实际落地的路（2026-10 更新）

最后没有走上面任何一条"整首合成"的路，而是：**从 CC BY-SA 语料里切真人元音 + 浏览器里 TD-PSOLA 变调**。

### 找素材时踩到的坑（省得再查一遍）

| 素材 | 结果 |
|---|---|
| VCSL（CC0，GitHub） | 只有管乐/弦乐/打击乐，**没有人声** |
| Dirt-Samples（CC0） | 没有 vowel/voice 目录 |
| VSCO 2 CE 的 GitHub 镜像 | 只有 Brass/Keys/Strings/Woodwinds/Percussion |
| Freesound 筛 CC0 | 只有零散单条（"CRWDSing_Ahh" 是游戏展的群众合唱、只有一个音高一个元音），**凑不出 5 个元音 × 多音高** |
| HuggingFace 上的 singing 数据集 | 要么 CC-BY-NC，要么 190 GB 级网络抓取数据（版权不明） |
| **PJS 语料** | ✅ CC BY-SA 4.0、48 kHz、**带音素级 .lab 标注**、100 首歌、260 MB、可商用（署名 + 相同方式共享） |

结论：**CC0 世界里没有"成套的真人歌唱元音"**。要真人嗓子，PJS 是最省事的合法来源。

### 落地实现

- 切库：`tools/svs/build_bank.py`
  - 读 `.lab`（HTK 100ns 单位）→ 挑时长 ≥ 0.55 s 的 a/i/u/e/o
  - 自相关测 F0，只用音高稳定（`std/mean < 2%`）的段 —— 避开带颤音的长音，否则 PSOLA 会和自己的颤音打架
  - 每元音按音高挑 4 档 → 17 条样本，降到 22.05 kHz，归一化
  - 输出 `assets/voicebank.js`（base64 int16，0.63 MB）
- 变调：`src/js/voxsample.js` 里的 `voxPsola()`
  - TD-PSOLA：汉宁窗、2 个源周期一粒、50% 重叠、源位置插值
  - 变调保共振峰（playbackRate 会变"花栗鼠"）
  - **坑**：源周期不是整数个采样点（44.1k/137.55 Hz = 320.61），直接 `x[s]` 取到的是 `undefined`，一路 NaN。必须插值。
- 接入：`audio.js` 的 `voxV()` 有音库时走 buffer 路径，没音库自动退回原波表。

### 验收

- `node tools/svs/test_psola.js`：6 个音的实测基频与目标差 ≤ 16 音分，`nan=0`
- `?selftest=1&short=1&n=2`：peak 0.891 / 0.899，nan=0，WAV ok，渲染 1.6–1.8 s
- 人声相对伴奏 +2.6 dB（夜之城，32 拍片段）

### 第二轮修订（试听后的问题）

用户听完 `demo-vox-sample.wav` 给了四条，逐条对根因：

| 反馈 | 根因 | 改法 |
|---|---|---|
| 人声之间没连贯性，像"啊-诶-啊"连起来，很急 | ① 一个音符 = 一个词，143 BPM 下每 0.2 s 重新咬一次字 ② 每个音节都换元音，而且"撞上同一个元音还强制换" | `score.js`：短音符**接在上一个词尾巴上**（连唱，`voxChain`），一个词可跨 4.5 拍；口型默认沿用，只在换词时换（约两秒一次） |
| 辅音认不出来 | 每个辅音只有 ~40 ms，比元音低 14 dB，频谱又都挤在 2–3 kHz | `CONS_SPEC` 加 `kind`：爆破音＝40 ms 闭气 + 18 ms 爆点；擦音＝110–150 ms 气流；近音＝最轻最短。音量提到比元音低 5–8 dB |
| 口型之间交叉淡化、过渡不好 | 交叉淡化最多 70 ms，等于"切"过去 | 拉到 90–220 ms（上限为段长的 45%），并用**等功率（sqrt）曲线**；段内换口型的淡入淡出都走 sqrt |
| 人声音量有点大 | 峰值 `vel*0.75`，比伴奏高 2.6 dB | `vel*0.52`（−3.2 dB）→ 实测 −0.6 dB（夜之城）/ −0.4 dB（黎明海面） |

另外把**词与词的交界**也接平：`buildScore()` 末尾给相邻的 vox 事件打 `holdEnd`（前一句不收音、撑过交界再淡出）+ `legato`（后一句从 0 起），两边都是同元音，线性交叉刚好接平 —— 旧版后一句从 55% 起，交界会顶一下。

验收（`?selftest=1&short=1&n=3`，全部 `nan=0`、`peak≈0.89`、`WAV ok=true`）：

| 曲子 | 词数（旧 → 新） | 平均词长 | 最长词 |
|---|---|---|---|
| 夜之城 electro 143 | 224 → 61 | 0.71 s | 2.38 s |
| 黎明海面 cinema 74 | — → 68 | — | 1.10 s |
| 森林 folk 91 | — → 42 | 1.16 s | 3.06 s |

### 第三轮修订（"每个音都不全" + "电噪声"）

这轮没靠猜，逐项量出来的（`node tools/svs/analyze_wav.js <某个.wav>` 可以复现）：

| 现象 | 是 / 不是 | 证据 → 改法 |
|---|---|---|
| 真的噪声？ | **不是** | 人声轨频谱平坦度 0.003–0.02（白噪声 ≈ 1）→ 没有静电噪声，是"电音味" |
| 辅音太噪？ | 不是主因 | 把辅音全部关掉再量，跳变/断层一个不差；辅音整体只有 −29 dB |
| 每个音都不全 | **是** | 音节中位 0.16–0.21 s，一个词 1.5 s 里有 8 个音 —— 耳朵来不及听出音高。→ 加 `MIN_SYL = 0.30`：太短的音并进前一个音（像一个长音），中位升到 0.42 s |
| 段内电平忽大忽小 | **是（最关键）** | PSOLA 的重叠相加增益 = `窗宽 /(2×跳距)`，窗宽随音高变 → 唱高音电平凭空高 5–6 dB。→ 每粒乘 `op / max(sp, op)` 补偿 |
| 段与段交界塌一块 | **是** | 交叉淡化时长按"各自段长"算，淡入比淡出长 → 中间掉 8 dB。→ 改成**按边界**算一次、两边共用 |
| 响度不一致 | **是** | `voxPsola` 按**峰值**归一化，亮的元音比暗的响好几 dB。→ 改成按 **RMS** 归一（0.22，峰值兜底 0.98） |
| 电音味 | 部分 | 全曲固定 5.3 Hz 颤音 + 完全准的音高。→ 每个词自己的颤音速率（4.4–6.1 Hz）+ ±5 音分音准偏差 + 慢速漂移 |
| 滑音吃掉音 | 是 | 每粒固定 45 ms 滑音，在 0.16 s 的音上占掉一半。→ 滑音改成音长的 1/5（15–40 ms） |

另外 PSOLA 内核两处修正：
- 源位置**只能整周期跳**（`acc` 累积量决定这一粒跳 0/1/2 个周期）。原来的小数步进会让相邻两粒落在相反相位上互相抵消 → 音色发毛。
- 窗长改成 `2 × max(源周期, 输出周期)`。只按源周期算窗，变调后粒与粒之间会露缝。
- 循环读样本时两端各留 25 ms（音库样本两端有 15 ms 淡入淡出，读到就会掉电平）。

验收：人声轨 606/670 个 10 ms 帧在发声，发声帧内 5% 分位的电平是中位的 0.50（改前段内有 0.22 的塌陷）；人声相对伴奏 夜之城 −0.6 dB / 黎明海面 −2.2 dB / 森林 +3.9 dB。

### 第四轮修订（"突然一段很短的沙沙声"）

先定位：把人声轨按 5 ms 切帧，算**高频占比**（一阶差分能量 / 总能量，平坦白噪声 ≈ 1）。
抓到一处 165 ms、`hf ≈ 1.0` 的段，正好落在词 4 的字头位置 —— 是 `/h/`。

然后用 PJS 里**真人辅音**量了一遍能量分布，才发现问题不是"有噪声"，而是**频率放错了**：

| 音素 | 真人能量（10 % / 中位 / 90 %） | 我原来的合成参数 |
|---|---|---|
| /s/ | 5.9k / 8.7k / 12.8k Hz | highpass 5k，**一直到 22k**（多出 10k 以上的一截） |
| /sh/ | 3.8k / 5.3k / 8.4k Hz | bandpass 2.9k，同样太宽 |
| **/h/** | **188 / 398 / 1605 Hz** | **highpass 1500、150 ms、g 0.46** —— 完全错，真人 /h/ 是低频呼气 |
| /t/（爆破） | 23 / 352 / 2859 Hz | bandpass 3200 —— 也偏高 |

三个结构性毛病叠在一起：

1. **白噪声一直到 22 kHz**，多出来的高频就是"沙"。真人的 /s/ 到 13k、/sh/ 到 10k 就掉下去了 → 每个擦音后接一级 `lowpass`。
2. **/h/ 被做成了最亮最长的那个**（highpass 1500 + 150 ms + 最大增益），而它本该是最轻的。→ 改成 bandpass 900 Hz / Q 0.7 / 95 ms。
3. **辅音和元音之间是断开的**：擦音在元音起点就结束，元音再从零爬 50 ms，中间空一段 → 听成"一段悬空的沙沙声"。→ 擦音尾端压到元音起点**之后 28 ms**，元音起音在带字头时缩到 25 ms，两者真的叠在一起。

另外把 `/s/` 从"软情绪"辅音池里拿掉（软情绪用 l/n/m/v/w/y/h/r，擦音留给硬情绪），并把近音的增益提了 3 dB（实测它们比元音低 29–33 dB，太轻了）。

验收（同一段 11.15–11.25 s 的 /h/ 窗口）：

- **10 kHz 以上能量占比 23.2 % → 0.1 %**（降了 230 倍，这就是"沙"）
- /h/ 相对元音 **−16.5 dB → −25 dB**（真人 /h/ 的合理区间是 −20 ~ −25 dB）
- 各辅音相对元音：s −17.6 / sh −19.7 / ch −22.4 / h −25.0 / 近音 −29 ~ −30 / 爆破 −35（RMS，爆破的峰值另算）

### 第五轮修订（"听不出像唱歌，全是一沃一沃"）

沙沙解决后，剩下的问题是**没有"字"**。查了三个数字：

| 指标 | 改前（夜之城） | 问题 |
|---|---|---|
| 相邻音节换口型 | **10 %** | 一条十秒的句子从头到尾同一个元音 → 只剩"呜——" |
| 音节有字头 | **30 %** | 连唱时 `chainOk` 分支把 `cons: null` 写死（"词中间不咬字"）→ 词中间 100 % 无辅音 |
| 音节中位长 | 0.42 s | 上一轮的 `MIN_SYL = 0.30` 把带字的短音也一并并掉了 |

三个原因叠起来，就是"148 个音共用一个口型、一个没字头"的拖长音。改法：

1. **口型每音节大概率换**（10 % → 62 %，并保证不连着两个相同）→ 相邻换口型 95–98 %。
2. **连唱时保留字头**（`cons: s.cons` 而不是 `null`），词中辅音概率 0.18 → 0.50 → 有字头 74–90 %。
3. **`MIN_SYL` 改成按拍算（半拍）+ 例外**：带字头或换口型的音节只要 ≥ 0.11 s 就保留，纯音高变化才要求半拍。这样"音高能听清"和"有字"不再互相排斥。
4. 交叉淡化下限 0.09 → 0.045 s（音节变短到 0.2 s，淡化必须跟着变短，否则口型换不动）。

验收：

| 曲子 | 音节数 | 有字头 | 相邻换口型 | 音节中位长 |
|---|---|---|---|---|
| 黎明海面 | 105 → 168 | 57 % → **74 %** | 33 % → **95 %** | 0.81 → **0.32 s** |
| 夜之城 | 148 → 225 | 30 % → **90 %** | 10 % → **96 %** | 0.42 → **0.21 s** |
| 森林 | 143 → 208 | 24 % → **75 %** | 15 % → **98 %** | 0.66 → **0.33 s** |

辅音多了 4 倍，但 >8 kHz 能量占比从 0.13 % 变成 0.12 % —— 说明"沙"没有回头（因为上一轮已经把频谱切对了），变密的只是低中频的咬字噪声。

### 第六轮修订（"一个音的结尾和下一个音的开头重合了"）

这一条不是玄学，是包络写错了方向。

| 位置 | 旧 | 问题 |
|---|---|---|
| 段与段之间 | 淡出 `[sb-xf, sb+xf]`，淡入 `[sa-xf, sa]` | 淡出比淡入长一倍，**新音已经到了满音量，旧音还在往下掉** —— 听得见两条声音同时存在 |
| `holdEnd` 词交界 | 前词 `[sb-0.01, sb+0.11]`，后词 `[sb, sb+0.11]` | 110 ms 双向重叠，而且常常是两个不同的音高 |
| `xfAt` 上限 | 100 ms | 音节只有 0.21 s 时，重叠占了半个音节 |
| 颤音相位 | 按"段内时间"算 | 两段一重叠，两条颤音相位不同 → 互相拍，加重"两条声音"的感觉 |

改法：

1. **淡出止于交界**：非末段 `relEnd = sb`（原来 `sb + xfOut`）。上一段在 `[sb-xf, sb]` 淡完，这一段在 `[sa-xf, sa]` 淡满，两边同宽互补，交界之后**只剩一条声音**。
2. `xfAt` 上限 100 → **55 ms**，比例 0.35 → 0.22（上下限 20–55 ms）。
3. 词交界：`holdEnd` 收到 `[sb-0.035, sb]`，后一词从 `sa-0.035` 淡入，两边各 35 ms。
4. 颤音/漂移改用**相对整个词起点**的时间（`atW = at + sg.a`），相位跨段连续，不再互拍。
5. 波表 fallback 的包络改成同一套数（否则有/没音库听起来不一样）。

验收（给 `voxRenderSegment` 和 `createBufferSource` 打桩，直接量每两段在时间轴上的重叠）：

- 改名前后：约 200 ms → **中位 48 ms、最大 58 ms**（25 段）
- 自检 `nan=0`、`peak<1.0`、`WAV ok=true`、0 条 console error；爆点计数 86 → 97（和鼓的瞬态同量级，不是咔哒声）
- 副作用：人声整体 RMS 0.1386 → 0.1314（−0.5 dB）—— 重叠去掉后"双声"叠加的能量没了，音量本身更干净

### 第七轮修订（"一串伊瓦伊艾伊，每个音太近了"）

三条独立原因，都能测：

| 指标 | 改前（夜之城） | 原因 |
|---|---|---|
| 元音里 `/i/` 占比 | **28–30 %** | `pickVoxVowel` 有 55 % 直接取"想音"，夜之城情绪是 `ki` → 元音 `i`，一半以上的字都是"伊" |
| 剩下 45 % | 随机抽 `HYMN_NUCLEUS` | 里面混着 `o/e/a/u`，连起来就是"伊—瓦—伊—艾" |
| 音节中位长 | **0.21 s** | `MIN_SYL = 0.5 拍`，143 BPM 下 0.21 s；而且词内音节按 `head`（时间值）切，落在 +0.088 s 这种**拍与拍之间** |

改法：

1. **`MIN_SYL` 改成 1.3 拍（0.40–0.70 s）**：一个"唱出来的字"至少一拍多。0.21 s 是连珠炮，
   而且并音同时也把拍外的音节并掉了 —— 节奏跟着变准（落在八分格上 80–96 %）。
2. **口型按音长分配**：长音只用开元音 `a/o/u/e/i`（加权偏开），"想音"只在开元音时给 35 %；
   亮窄的 `i` 从 28 % 降到 9–15 %。理由是 `i` 拖 0.6 秒会发尖，这不是"情绪"是"刺耳"。
3. **口型去重挪到合并之后**：口型在合并前分配，被并掉的音节会让留下来的相邻两个撞成同一元音
   → 又变回"一条长音在拖"。补一遍按合并后顺序的去重（跨词也算）→ **相邻换口型 100 %**。
4. 词中字头概率 0.50 → 0.40（音节变长了，不需要每个音都咬）。
5. 顺手修了自检里的 `syl=`：它量的是音节自己的 `d` 字段，并音只延长前一个音的 `d`，
   拿 `d` 统计会**低估**（显示 0.21，实际 0.63）—— 改成量"到下一个音节的间隔"。

验收：

| 曲子 | 音节数 | 有字头 | 相邻换口型 | 音节中位长 | `/i/` 占比 |
|---|---|---|---|---|---|
| 黎明海面 | 79 → 78 | 86 % | 100 % | 0.32 → **0.89 s** | 30 → 9 % |
| 夜之城 | 104 | 87 % | 100 % | 0.21 → **0.63 s** | 28 → 15 % |
| 森林 | 88 | 72 % | 100 % | 0.33 → **0.99 s** | 17 → 9 % |

自检 `nan=0`、`peak<1.0`、`WAV ok=true`、0 条 console error。

> 排障记录：改完 `selftest.js` 后同一端口复测，`syl=` 仍显示 0.21 —— 是浏览器用了缓存的旧脚本。
> 换一个新端口（新 origin）立刻变成 0.63。**改完 JS 一定要换端口验**，否则看到的是上一版的数。

### 第八轮修订（"能听清每个字了，但还是不好听"）

先把塔语歌曲本身重新查了一遍。之前 `03-hymmnos.md` 只记了**唱法**（志方あきこ的
真假声切换、上滑进长音、长音元音微变、给自己叠三度和声），漏了**编曲**这一层。
这一轮补到的关键事实：

| 事实 | 出处 |
|---|---|
| 塔语歌的核心是**多重コーラス**。土屋暁说他试过所有"合唱"音色都不够厚，最后同一句叠了 **A–F 六个声部**，才做出"超コーラス曲" | 志方あきこ / 土屋暁 对《謳う丘 -Harmonics EOLIA-》的访谈 |
| 和声层不是"伴唱"，是**和主唱平行的另一条旋律线**，两线同时唱不同的词；主唱停顿处用回声填 | 同上，METAFALICA 的结构说明 |
| 旋律靠**排比**推进：`Was yea ra … / Wee yea ra …`、`Faura yerwe / Faura sonwe` —— 同一个动机反复，和音乐的模进天然对齐 | 同上 |
| 音色取向是**民族＋古典的庄重感**（弦乐、竖琴、人声铺底），不是电子 | 曲目评述 |

对照我们的输出，量了三个数，第一个就是硬伤：

| 指标（改前） | 黎明海面 | 夜之城 | 森林 | 真人唱歌的常态 |
|---|---|---|---|---|
| 相邻音级进（≤2 半音） | 49 % | **39 %** | 38 % | **70–85 %** |
| 跳 ≥5 半音 | 19 % | **45 %** | 45 % | < 15 % |
| 跳 ≥7 半音 | 4 % | **18 %** | 24 % | < 5 % |
| 音域 | 19 半音 | **36 半音** | **35 半音** | 12–20 半音 |
| 带和声层的事件 | 13/68 | 14/60 | 12/42 | 塔语歌几乎全程 |

**结论：人声根本不是"旋律"，是"把 lead 合成器的琶音一个一个念出来"。**
一个跨三个八度、一半是五度以上大跳的旋律，没有哪个歌手能唱，所以怎么调音色都不像唱歌。

改法三条：

1. **人声有自己的旋律，而且放在"并音之后"定音高。**
   旋律的"级进"必须发生在**真正唱出来的两个音**之间；在并音之前算，被并掉的音节不发声，
   剩下的相邻两音就隔了好几级（第一版这么写，测出来仍有 30 % 是七度以上大跳）。
   现在的规则：一个 6 音的**拱形动机** `[0,1,2,3,2,1]`（音阶级数），每重复一遍整体上一级
   （模进 `[0,1,2,3]`），装不下了往回退两度；强拍只允许被拉回 1 个半音以内的和弦音。
   音区固定在 C4–C5 附近（`voxOct` 独立于 `spec.melOct`）—— 音库是女声，
   被 PSOLA 拉到高音区会变形，上一版最高唱到 midi 93（A6）。
2. **人声变成"多重录音"三轨**（`playEvent` 的 vox 分支）：
   主轨咬字；副轨 ±7/9 音分、晚 21/38 ms、**不咬字**（几轨一起咬就是"打嗝"）。
   第三条只在 ≥0.5 s 的长音上给，否则渲染时间翻三倍还听不出厚度。
3. **和声层跟着新旋律走**：A″ 上方三度、A′ 后半下方三度，用"音阶上的三度"（`degAbove`）算，
   不是固定 +3 半音。

顺带查出一个一直没说破的坑：**`voxPsola` 把每段归一化到固定 RMS 0.22，
`vel` 到不了音频层** —— 也就是说上一轮"人声略大"之后调的 `peak = vel*0.52` 其实只在
调包络形状，音量一点没动。多轨叠录的相对音量只能靠 `voxToAudioBuffer(…, gain)` 给。

验收：

| 指标 | 改前 | 改后 |
|---|---|---|
| 级进（≤2 半音） | 39 %（夜之城） | **55 %**（五声：一级就是 2–3 半音）／**95 %**（自然小调） |
| 跳 ≥5 / ≥7 半音 | 45 % / 18 % | **0 % / 0 %** |
| 音域 | 36 半音 | **12 半音**（midi 58–70） |
| 落在和弦音上 | — | 82 %，强拍 81 %，撞小二度 **0 %** |
| 人声/伴奏 | −0.6 ~ +3.9 dB | **−1.9 dB**（夜之城） |

自检 `nan=0`、`peak<1.0`、`WAV ok=true`、0 条 console error；
peak 从 0.916 降到 0.81–0.90（总线压缩器不再被顶死，动态回来了）。

### 第九轮修订（"感觉对了，但没有那种灵动感"）

前两轮都只在"音色/音高"上做功，这一轮先回到源头查**音乐本身**。
再查一遍志方あきこ，官方简介里反复出现的一句是
「**民族的なリズム**と、緻密なコーラスワーク」——"民族节奏"不是形容词，
它是具体的：不落在规则的格子上的弱起、切分、长短交替。

对照我们的输出，问题一眼就能看出来：

| 指标（第九轮前） | 黎明海面 | 夜之城 | 森林 |
|---|---|---|---|
| 字的实际长度（中位） | 0.89 s | 0.63 s | 0.99 s |
| 一个音里唱几个音高 | **1** | **1** | **1** |
| 起音位置 | 全在拍点 | 全在拍点 | 全在拍点 |
| 每个字的音量 | 全一样 | 全一样 | 全一样 |

**每个字都稳稳压在拍点上、每个字都一样长、每个字都只有一个音高、每个字都一样响** ——
这是节拍器，不是人。第八轮把音节拉长到 0.6–1 s 修掉了"连珠炮"，
但同时把短音全并掉了，长短交替、装饰音也跟着一起没了。

四处改法（都在通用引擎里，没有任何按歌/按图的分支）：

1. **转音（melisma）**：在一个字里连唱 2–3 个音，**同口型、无字头**。
   音频层会把它们当成同一条音线做音高滑移，所以听上去是"这个字的尾巴转了一下"，
   而不是"又唱了一个字"。这是"灵动"最直接的来源。
   **关键：必须放在并音之后** —— 只有真正唱出来的音才知道自己有多长。
2. **元音微变**：没有转音的长音（≥0.7 s），后 28% 把口型往开的方向挪一点（a→略带 o），
   就是 `03-hymmnos.md` 里记的志方唱法第四条，拖到现在才做。
3. **抢拍（anticipation）**：真唱是从拍子**前面**起音的 —— 辅音先到、元音落在拍上。
   我们以前是"拍点起、先咬 60 ms 再出声"，所以每个字都晚一步，听着就沉。
   现在只在前面的空隙 ≥0.12 s 时抢，最多 60 ms，不会和上一句叠起来。
4. **重音**：强拍的字 1.07×、弱位 0.94×（`voxGain`）。整句一样响就是机器人在念。

验收：

| 指标 | 第九轮前 | 第九轮后（黎明海面 / 夜之城 / 森林） |
|---|---|---|
| 转音数 | 0 | 105 / 56 / 117（每词 1.5 / 0.9 / 2.8 个音） |
| 元音微变 | 0 | 13 / 7 / 10 |
| 抢拍 | 0 ms | 60 / 60 / 60 ms（有 60 ms 上限） |
| 发音帧（28 s 片段） | 2233/2799 | **2384/2799** |
| 频谱平坦度 | 0 | 0（没有回头变"沙"） |
| 爆点 | 114 | 117（同一量级，不是咔哒） |

自检 `nan=0`、`peak<1.0`、`WAV ok=true`、0 条 console error；
渲染时间没变（转音不增加 PSOLA 段数，只增加音高折点）。

> 顺带修了 `selftest.js` 的 `syl=`：它现在会把 0.09 s 的转音也统计进去（min 显示 0.11 s），
> 所以另加了 `orn=` / `gl=` 两个计数，否则下一轮会误判成"又变回连珠炮了"。

### 第十轮修订（"每个音的尾声都往上扬"）

> 用户反馈：**"现在听起来每个音的尾声都是往上扬的是吗，感觉不太贴合正常唱歌的感觉。
> 然后想办法找找资料，模拟人声的做法。"**

前半句是我的 bug，后半句正好是这一轮真正该做的事。

**① 尾声上扬：转音形状写错了。**
第九轮的形状是 `[主音, +1级, +2级]`，**收在高处**，所以每段转音都把音拖起来 ——
那不是唱歌，是语气词。改成"每条形状的最后一个偏移必须是 0"：

| 形状 | 走向 | 权重 |
|---|---|---|
| `[2,1,0]` | 上回音：上两级再落回 | 34% |
| `[1,0]` | 短上回音 | 24% |
| `[-1,0]` | 下回音：往下探一下回来 | 20% |
| `[-2,-1,0]` | 下绕 | 10% |
| `[1,2,0]` | 大上回音 | 12% |

音符太短就砍成两音收尾（`shape.slice(-2)`），否则每个音只剩几十毫秒会糊成一片。
验收：**89 段转音里，落点高于主音 0 段、低于主音 0 段、回主音 89 段。**

**② 查资料：人声到底靠什么才像人声。**

埼玉大学那篇《歌声知覚・生成機構の解明に向けた歌声合成システム構築に関する研究》
把歌声的基频动态拆成四个成分，并按对"像不像唱歌"的贡献排了序：

| 成分 | 是什么 | 我们之前 |
|---|---|---|
| **オーバーシュート（冲过头）** | 起音先略微超过目标音高，再落回来 | **完全没有** |
| ビブラート（颤音） | 5–8 Hz，幅度 < 1 个半音 | 有，但速率 4.4–6.1 Hz 偏低 |
| プレパレーション（预备） | 起音前的微小音高移动 | 只有 14 音分的上滑 |
| 微細変動（微细抖动） | ±3 音分左右的不规则抖动 | **完全没有** |

论文的结论是：**冲过头是歌声知觉中最基本的一项**，颤音则区分唱功高低。
KTH 那篇颤音综述给出的实测区间是 5–8 Hz、幅度小于一个半音；
频谱侧还有 singers' formant（约 3 kHz 的共振峰）和与颤音同步的共振峰振幅调制。

注意：**冲过头不是装饰音，是每个音都有**。少了它，每个音都"啪"地对准目标频率，
就是合成器；多了它，音才有"够上去又稳住"的那个动作。

**③ 改动**（全部在 `audio.js` 的 `f0At`，通用，无任何按歌/按图分支）：

- **冲过头**：每个音的落点先高 `20–44` 音分，再按 `exp(-t/85ms)` 沉回目标（0.32 s 内有效）。
  只对 ≥0.24 s 的音做 —— 转音里那些 70–110 ms 的音会被抹平。
  段首那个音只给 20 音分，因为它已经有一条 14 音分的"找音高"上滑，不然叠成一个大弯。
- **微细抖动**：`7.7 Hz × 2.4 音分 + 12.3 Hz × 1.4 音分`（+ 原有的 0.71 Hz 慢漂移 ±6）。
  这一项和颤音无关、短音上也有 —— 它是"气息"的证据，不是"技术"。
- **颤音速率**：`4.4–6.1 Hz` → `5.0–6.6 Hz`，并给相位加一条 0.37 Hz 的慢调制，
  让速率本身也在晃（真人的颤音不是节拍器）。
- **转音内部的滑音**：`0.2 × 间隔`（下限 15 ms）→ `0.32 × 间隔`（下限 18 ms），
  转音每一步只有 70–110 ms，旧的系数会让它滑不到一半就被下一个音截断。

**④ 验证**（只渲染一个 1.2 s 长音，40 ms 窗自相关测基频）：

```
起音 −5 音分 → 85 ms 冲到 +13 → 300 ms 沉回 0 → 200–300 ms 之间 ±2 音分抖动
```

形状对上了：**冲上去、落回来**，不是一条平线。

| 指标 | 第九轮 | 第十轮 |
|---|---|---|
| 转音落点往上扬 | 100% | **0%（89/89 回主音）** |
| 冲过头 | 无 | 20–44 音分，τ=85 ms |
| 微细抖动 | 无 | ±3.8 音分 |
| 颤音速率 | 4.4–6.1 Hz | 5.0–6.6 Hz + 速率晃动 |
| 发音帧 / 爆点（28 s） | 2384 / 117 | 2379 / 117 |

自检 `nan=0`、`peak<1.0`、`WAV ok=true`、0 条 console error；渲染时间不变。

**⑤ 刻意没做的**：singers' formant（约 3 kHz）——我们的音源是真人录音，
共振峰本来就在里面，再加一层抬升只会变尖；共振峰振幅调制（与颤音同步）需要
每帧重算包络，成本远高于收益。这两项记在这里，留到"还要更像人"的时候再说。

### 第十一轮修订（"比较乱，没有音韵的协调美"）

> 用户反馈：**"现在这个人声听起来比较乱，没有那种音韵的协调美。"**

这次不是音色问题，是**音韵**问题 —— 也就是"这些音节读起来像不像一句话"。

查下来，病根在 `pickVoxVowel` 的一条老规矩：

```js
if (v !== cur) return v;   // 永远不等于上一个口型
```

再加上"每个音节独立抽一个元音"，一句话能唱出 **a-e-i-o-u**。
这在押韵学里是**反着来的**。母音韻（assonance）的定义是：
*相邻的词重复同一个元音，产生内在的共鸣与音乐性*，而且
"気づかれるよりも、感じられるときに最もよく働く"（被感觉到比被听出来时最有效）。

那条"永远不等于上一个"是更早几轮为了修"一条长音在拖"加上的 —— 但它修错了地方：
真正导致"拖"的是**两个音节之间没有辅音重新咬字**，不是元音相同。

另外两条作词经验也直接可用：

- 日语作词理论：**あ段最亮**（副歌头爱用）、**う段口开得最小、最发不出力**（别用在要冲的地方）、
  **え段偏弱但适合句末长音**、**か行/た行最有力**、**さ行/は行最轻最顺耳**、**ら行难唱、出现率低**。
- 某首 J-POP 被专门分析过：**副歌最高音都落在 a / e / o 上**，因为口型开、发得舒服。
  物理原因更硬：唱高音时基频 F0 会超过 i / u 的第一共振峰，**那个元音在高音上根本发不出来**，
  真人会自动张嘴换成 a / e / o。

**改法**（全在 `score.js`，四层）：

1. **每句一种"元音颜色"**：`VOX_COLORS` 里 8 组双元音（只用 a/o/e/u，不要 i），
   一句之内 **68%** 的字落在这两个元音上。颜色由"想音"决定（一定含情绪元音），换句才换色。
2. **押韵构成 A-A-B-A**：第 1、2、4 句同色，第 3 句换色。
   第 3 句变一次色，耳朵才知道"这是新的一句"，而不是从头到尾一个味道。
3. **头韵**：每句抽 3 个辅音当色板，词首基本只用这 3 个，词中一半用它们。
   实测每句的辅音种类是 **2–4 种**（设定 3 个）—— 一句话反复咬着同一组字头。
4. **放宽"不同口型"**：只有**没有字头**的相邻音节才强制换元音。
   有字头时同元音是正常的复沓（"la-la"），辅音会重新咬一下，不会拖。
   这一条是同口型首次被允许 —— 以前它是被一刀切禁掉的。

顺带加的物理约束：**G4 以上强制换成 a/e/o**（i/u 的第一共振峰低于 F0，发不出来）。

**验收**：

| 指标 | 第十轮 | 第十一轮（黎明海面 / 夜之城 / 森林） |
|---|---|---|
| 相邻同元音 | 10% / 1% / 0% | **46% / 45% / 33%** |
| 每句元音熵 | 1.87 / 2.09 / 2.01 bit | **1.21 / 1.11 / 1.39 bit** |
| 高音上的 i/u | 3/18、9/28、1/7 | **1/19、0/28、1/6** |
| 元音主色 | 五个元音平摊 | 夜之城 o:51 a:39，森林 o:40 u:18 |
| 每句辅音种类 | — | 2–4 种（设定 3） |
| 爆点（28 s） | 117 | **98** |

爆点从 117 掉到 98，是因为换口型的次数少了 —— 交叉淡化少了，音线自然更整。
自检 `nan=0`、`peak<1.0`、`WAV ok=true`、0 条 console error，渲染时间不变。

**参数位置**：颜色占比是 `pickVoxVowel` 里的 `r < 0.68`，调大更"统一"、调小更"变化"；
押韵构成是 `COLOR_SCHEME = [0,0,1,0]`。这两个是"乱 ↔ 单调"之间的那根弦。

### 第十二轮修订（"还是一串字母在唱" + "唱到一个音突然就到下个音"）

用户的两个问题，一个在设计层，一个在参数层。

#### 1）"一串字母"：因为没有词表

先量了一下"一个词有几个音节"（`e.syl` 里 `w0` 标记的词首切分）：

| | 词数 | 主音节 | 每词音节 | 不同词形 |
|---|---|---|---|---|
| 黎明海面（改前） | 69 | 77 | **1.1** | — |
| 夜之城（改前） | 57 | 100 | 1.75 | — |
| 森林（改前） | 41 | 85 | 2.1 | — |

`黎明海面` 平均**一个"词"就是一个音节**。而且每个词都是当场用 `rng()` 抽出来的，
整首歌没有任何东西重复过 —— 耳朵听到的当然是"字母"，不是"词"。

两条原因叠在一起：

1. **音节数由音符长度决定**（`nsyl = total<0.5?1:...`），词是音符的切片，没有词形；
2. **并音把词内部音节全并掉了**。`VOX_MIN_SYL` 要求字间 ≥1.3 拍，而词内音节只隔 0.13–0.2 s，
   于是 3 音节的词并完只剩 1 个。

对照 `03-hymmnos.md` 记的音位规律，本来就有三条没做：**一个词 2–4 音节**、
**相邻音节不重复声母**、**词尾必须是开元音**；再加上歌词里最显眼的那条 ——
**排比**（`Faura yerwe … Faura sonwe …`），靠的是**词在重复**，我们一次都没重复过。

改法（`score.js`）：

- **建词表 `LEX`**：按 seed 生成 14 个词，每个 2–4 音节、全开音节、
  词内相邻音节不重复声母、词尾强制开口大的元音。
- **词内元音和谐**：每个词只从自己的 1–2 个元音里取。
  这样"一个词"才是一个整体，而不是几个音节拼起来。选词时再挑元音颜色对得上本句的
  （和第十一轮的母音韻/押韵并存），于是"句有句色、词有词形"。
- **排比**：30% 直接重复上一个词。
- **并音只并整个词**：词内音节（`mid`）不参与并音，词头被并掉则整个词一起丢掉
  （否则剩下的音节会挂到上一个词尾巴上，森林那首实测出现过 7 音节的"词"）。
- **旋律只在词首推进**（`w0`）：一个词唱在一个音高上，词内音节同音。
  以前每个音节都推一级动机，一个词会被拆成一条快速琶音。

| | 词数 | 每词音节分布 | 不同词形 | 相邻同词 |
|---|---|---|---|---|
| 黎明海面 | 73 | 2音:27 3音:19 4音:27 | 43/73 | 6 |
| 夜之城 | 107 | 2音:90 3音:3 1音:14 | **34/107** | 21 |
| 森林 | 75 | 2音:42 3音:30 4音:3 | 43/75 | 7 |

#### 2）"突然就到下个音"：是设计，但形状写坏了

在谱面上复现了 `voxV` 的滑音公式，统计"段内换音"：

| | 换音次数 | ≥2 半音且滑音 <30 ms | 最大音程 |
|---|---|---|---|
| 黎明海面（自然小调） | 76 | **0** | 4 半音 |
| 夜之城（小调五声） | 80 | **11** | **5 半音** |
| 森林（小调五声） | 82 | 2 | 5 半音 |

差别不在滑音，在**音阶的度数宽度**：转音形状里有 `[2,1,0]`，第一步就走**两级**；
自然小调里两级 = 3–4 个半音，五声里两级 = **5 个半音**。再用 28 ms 滑过去 ——
那不是转音，是跳过去。

改法：

- **形状每一步只能走一级**，且最后必须落回主音：
  `[1,0]`(40%) / `[-1,0]`(28%) / `[1,2,1,0]`(16%) / `[-1,-2,-1,0]`(16%)。
- **滑音时长按音程给**（1 半音 19 ms、3 半音 57 ms、上限 75 ms），
  且不超过前一个音的间隔的 85%，否则折点会倒序、插值直接失效。
  原来是按"这个音有多长 × 0.32"，间隔 80 ms 的音就只给 26 ms。

改后：**三首硬跳全部为 0**，`bp` 倒序 0，最大音程 2/3/4 半音。

#### 3）验收

`?selftest=1&short=1&n=3`：`nan=0`、`peak=0.855/0.860/0.859`、`WAV ok=true`、
0 条 console error，渲染 10.6/8.7/10.7 s（未变慢）。
`analyze_wav.js` 对同一段 26.8 s：爆点 108（v14 同长度折算 94）——
多出来的是词内音节的字头，不是杂音。

**参数位置**：词表规模与结构是 `score.js` 的 `LEX` 生成段（14 个词、2–4 音节、
`PAL_V` 词内元音池）；"重复上一个词"的比例在 `pickWord` 的 `rng() < 0.3`；
词内音节长度是 `head = clamp(total*0.22, 0.095, 0.30)`；
转音形状在后处理的 `shape` 选择；滑音公式在 `audio.js` `voxV` 的 `glide`。

### 第十三轮修订（"很怪，没有唱歌的感觉"）

这一轮不是音色问题，是**节奏问题**。查完文献再量，发现我们做反了。

#### 1）文献：唱歌与说话的区别主要在"元音的长度"

- **唱歌是把元音拉长，辅音几乎不拉长。** 普通话说话数据里元音占比 51.6%–74.6%；
  英语塞音在唱/说之间的时长比只有约 1.4 —— 也就是说一个音拖到两秒，
  也不是把"b"拖成两秒，而是把后面的"a——"拖长
  （Zhang et al., *Segment Duration and Proportion in Mandarin Singing*, Speech Prosody 2020）。
  语音转歌声（SPS）的标准做法也是：辅音/过渡段基本不动，**把元音段拉伸到音符长度**
  （Umbert & Bonada, *Expression Control in Singing Voice Synthesis*, IEEE SPM 2015）。
- **每个音要有足够的长度，颤音才存在。** 真声颤音 4.5–6.5 Hz、幅度 50–120 音分（峰峰值），
  而且**是"先直后抖"**：起音后 0.2–0.5 s 才起来（ICPhS 1999 的颤音起始研究）。
  一个 0.1 s 的音根本放不下一个颤音周期。
- 第十轮已经排过一次"像人"的四项权重：冲过头 > 颤音 > 预备 > 微细抖动。
  **这一轮发现：那四项全都建立在一个前提上 —— 音要够长。** 音不够长，前四项一个都用不上。

#### 2）量出来的病：音节中位 0.11 秒

按 `e.syl` 逐音节统计（排除转音/滑音）：

| | 音节数 | 中位时长 | <0.15 s 的音节 | 每秒音节 | 换音高比例 |
|---|---|---|---|---|---|
| 黎明海面（改前） | 203 | 0.25 s | 14 | 2.12 | 38% |
| 夜之城（改前） | 194 | **0.11 s** | **114** | 1.22 | 44% |
| 森林（改前） | 228 | 0.14 s | **151** | 1.90 | 30% |

`夜之城` 194 个音节里有 114 个在 0.09–0.15 s —— 那是**说话的语速**。
更致命的是，音频层的颤音门限是 `dur >= 0.3`（`vibMax` 18 音分）与 `dur >= 0.5`（30 音分），
**中位 0.11 s 意味着整首歌几乎没有颤音**。一条不带颤音、每秒换 3 个字、
每个字只有 0.1 秒的声音，无论音色多好，大脑都只会判成"念"。

#### 3）根因：上一轮把"词"塞进了同一个音符里

第十二轮为了让"词"听得出来，做成"一个音符上塞 2–4 个音节"，
每个音节被分到 `head = clamp(total*0.22, 0.095, 0.30)` 秒。
一个 0.42 s 的八分音符 → 两个 0.095 s 的音节。

**这件事在音乐上是反的**：真歌里是**一个音节一个音**（一个音拖长），
偶尔才反过来 —— **一个音节好几个音**（melisma / 转音）。
我们把这条关系整个颠倒了：一个音好几个音节。

#### 4）改法

1. **一个音节一个音。** 词表不变（2–4 音节的词、词内元音和谐、排比），
   但改由**跨音符的词游标**推进：一个词的几个音节落在相邻的几个音上。
   词仍然是听得出的整体（同口型、声母轮着来、词尾落长音），
   而每个音节有整个音的时值去拖元音。
2. **音高每个音节推进一次**（以前只在词首推进，词内音节同音高 ——
   一个词 3 个音节唱同一个音，听起来就是"念"）。
   动机从 1 条拱形扩成 4 条轮换（`VOX_SHAPES`），避免 6 个音一循环的机械感。
3. **短音不唱，接着上一个音拖。** 音符短于 `VOX_MIN_NOTE = 0.24 s` 时，
   不另起一个字，直接把上一个正唱着的音延长过去（旋律照走、口型不动）——
   真人处理快走句就是这样，一个长音吃掉一串短音。
   143 BPM 的八分音符（0.21 s）因此不再被切成半首歌的字。
4. **`VOX_MIN_SYL` 从 0.40–0.70 s 降到 0.22 s。**
   那个阈值是"塞音节"时代用来防止"伊瓦伊艾"的，现在音节本来就长，
   再按 0.55 s 并音会把真正的音节也吃掉。
5. **转音门槛 0.55 s → 0.80 s，概率 45% → 32%。** 音节变长之后，
   原来的门槛会让每个字都绕一下 —— 那是花腔，不是唱歌。

#### 5）改后

| | 音节数 | 中位时长 | <0.15 s | 每秒音节 | 换音高 | 每词音节 | 音域 |
|---|---|---|---|---|---|---|---|
| 黎明海面 | 84 | 0.79 s | 0 | 0.81 | 75% | 3.1 | 8 半音 |
| 夜之城 | 116 | 0.45 s | 2 | 1.44 | 86% | 2.6 | 12 半音 |
| 森林 | 141 | 0.32 s | 0 | 1.49 | 87% | 2.5 | 12 半音 |

- 中位音节时长 **×3～7**，落在"能拖住元音"的区间；
- **换音高比例从 30–44% 升到 75–87%**：每个字都在唱不同的音，不再是同音重复；
- 66–68% 的音节带字头（其余连着前一个音唱），辅音:元音 ≈ 1:8 —— 说话的比值是 1:1~1:2；
- 音节/秒 0.8–1.5（抒情段 1–2 音/秒，符合 `06-music-theory.md` 第 3.2 节的密度表）。

`?selftest=1&short=1&n=3`：`nan=0`、`peak=0.656/0.836/0.874`、`WAV ok=true`、0 条 console error。

人声因此也变响了：音节连成一片、几乎不留缝，同样的包络下 RMS 比旧版高约 2 dB
（`voxonly` 独奏只比整混音低 **0.7 dB**，目标是 1.5–5 dB）。
`voxPsola` 会把每段归一化到固定 RMS，改 `peak`/`vel` 没用，只能在
`audio.js` 的 `voxToAudioBuffer(…, gain)` 上收 —— 新增 `VOX_LEVEL = 0.75`，
改后独奏比整混音低 **≈2.1 dB**。

**参数位置**：音节时长与词游标在 `score.js` 的人声段（`voxWord` / `voxWordUsed` /
`VOX_MIN_NOTE`）；音高推进在函数末尾的"人声旋律"（`VOX_SHAPES` / `VOX_SEQ`）；
转音门槛在同段后处理；颤音门限在 `audio.js` `voxV` 的 `vibMax`。

### 第十四轮修订（"得有点那种歌词的感觉"）

第十三轮把音节拉长了，中位 0.45–0.79 s，听感已经从"念"变成"唱"。
但用户接着说：**像在唱，可不像在唱"词"**。

#### 1）病因：没有一个"词串"出现过第二遍

旧逻辑是**逐音现抽词**（`pickWord`）：每个音来了，按当前这句的元音色挑一个词，
只有 30% 会直接重复上一个词。于是：

| | 不同词形 / 词数 | 说明 |
|---|---|---|
| 黎明海面（改前） | 约 1 : 1 | 几乎每个词都是新的 |
| 夜之城（改前） | 约 1 : 1 | 同上 |

**歌词感的第一来源不是音色、不是咬字，是重复。** 一段音乐里，听众是靠
"同一串词又出现了"来判定"这是歌词"的：副歌回来的时候，词、顺序、落点全都一样。
我们的采样器每句都在重新掷骰子，等于一首没有副歌的歌 —— 每一个字都新，
大脑就把它归到"无意义的音节流"里去。这是念咒，不是歌词。

#### 2）改法：把词从"逐音随机"改成"按行复用"

1. **一句一行。** 生成 4 条"歌词行"：`CHORUS_LINES`（副歌 2 行）+ `VERSE_LINES`（主歌 2 行），
   每行 4–5 个词，词仍然来自 `LEX`（词内元音和谐、2–4 音节）。
2. **4 小节唱一行，行内按顺序取词。** 一个乐句开始时把游标归零，
   所以**每个乐句的第一个词永远是这一行的第一个词** —— 位置固定，耳朵才抓得住。
3. **段与段对齐。** 行号按"段内第几个乐句"取（`Math.floor(inSec / 4)`），
   不按全曲计数。于是 A 和 A′ 唱的是同一组行、同样的顺序；B/B′ 换成主歌那一组。
   副歌原封不动地回来 —— 这就是"副歌"。
4. **行首词做 hook。** 副歌两行共用同一个开头词，主歌两行共用另一个：
   "同样的第一个词一出来，耳朵就知道这是刚才那段"。
5. **长短相间。** 行尾那个词固定挑 3–4 音节的（它是这一句的落点，落在句末长音上），
   行内其他词随机；第 3 个词有 45% 概率重复第 1 个（排比，塔语歌词里最显眼的手法）。
6. **副歌的旋律也回得来。** 人声动机在 **A 段开头归零**（`voxDeg`/`voxSeq`/`voxNoteIdx`）：
   词一样、旋律也从同一个动机头起步，才是"同一个副歌"，否则只是"同样的词配了不同的曲"。

#### 3）改后

| | 词数 | 不同词形 | A 与 A′ 首句 |
|---|---|---|---|
| 黎明海面 | 28 | **11** | `3ko 3lo 2ya 4ho` / `3ko 3lo 2ya 4ho` ✔ |
| 夜之城 | 37 | **11** | `3wo 3ha 3wo 3mo` / `3_o 3ha 3wo` ✔（首词声母被丢了，长度一致） |
| 森林 | 39 | **17** | 段落交界处有词跨过去，首词不完全对齐 |

（`3ko` = 3 音节、声母 k、元音 o。改动前后对比最直接的一行是"不同词形"：
从 ≈1:1 降到 **1:2.3～1:3.4**，即平均每个词形在全曲唱 2–3 遍。）

`?selftest=1&short=1&n=3`：`nan=0`、`peak=0.719/0.847/0.862`、`WAV ok=true`、0 条 console error；
音节中位 1.12 / 0.84 / 0.99 s（第十三轮是 0.79 / 0.45 / 0.32 —— 因为词不再被音符切碎，
一个词的两个音节会连着落在相邻两个音上，反而更长）。

**参数位置**：行表在 `score.js` 的 `buildLine` / `CHORUS_LINES` / `VERSE_LINES`
（行数、每行词数、行尾长词、第 3 词排比都在这里）；行与段的对应在同一个函数的人声段
`if (inSec % 4 === 0)`；动机归零在末尾"人声旋律"的 `secIdxOf`。

**已知取舍**：一行 4–5 个词 ÷ 一个 4 小节乐句，意味着同一句在 8 小节里要唱两遍以上。
这是副歌该有的密度，但如果要更"叙事"，把 `buildLine` 的行长加到 6–7 个词、
并把行号改成按 `Math.floor(inSec / 8)` 取（8 小节一行）即可。

### 第十六轮修订（"两个正常的音之间夹着一个很短的音"）

第十五轮（音位架构：韵尾、想音、人称）记在 `03-hymmnos.md` §5.5，本节只说这一轮。

#### 1）先定位，再改

"很短的一个音"这种描述无法直接对应到代码，所以这一轮先做了四步定位：

1. 让用户把 20 秒人声单独听，**标出秒数**（他的标记有约 0.2–0.4 s 的反应延迟）。
2. 把同一段拆成 6 个分轨（人声/主旋律/琶音/低音铺底/鼓/全混），确认在**人声**里。
3. 在音库里逐条对比"标注基频 vs 实测基频"。
4. 对三处热点逐 20 ms 打印音量与音高（`tools/svs/probe_range.js`）。

第 4 步直接看到了病灶：正常人声在 260–450 Hz，而那几处出现了**稳定的 90 Hz 和 145 Hz**，
而且周期度（自相关峰）很高 —— 不是噪声，是真的有一个低八度的周期存在。

| 用户标记 | 当时应有的音高 | 实测 |
|---|---|---|
| 17.1 s | 440 Hz（A4） | **145 Hz ≈ 440/3**，持续 280 ms |
| 19.6 s | 367 Hz | **90 Hz ≈ 367/4**，持续 140 ms |
| 14.2 s | 329 Hz（E4） | 62→61→62→64 四个**0.085 s** 的转音音 |

前两个是变调算法的故障，第三个是谱面写得有问题 —— 两件不同的事，都要改。

#### 2）病因 A：取粒的窗和跳距不是同一个时间基

`voxPsola` 里，**窗长**取的是 `2 × max(源周期, 输出周期)`，而**跳距**是输出周期。
汉宁窗的叠加和只有在"窗长 = 2 × 跳距"时才恒等于 1；两者不等时，叠加和会按
`源周期 / 输出周期` 的节拍起伏。这个起伏的周期恰好是音高周期的 3–4 倍，
于是输出里凭空多出一个低八度/低三度的成分 —— 就是用户听到的"很短的低音"。

雪上加霜的是**相位漂移**：音库的基频是建库时测的，实测偏差最大 ±11 音分。
每取一粒就往后挪一个"名义源周期"，但真正的波形周期并不等于它，
误差粒粒累积；几十粒之后相位转过 180°，相邻的粒叠起来互相抵消，音量塌掉一块。

| | 改前 | 改后 |
|---|---|---|
| 恒定长音（2 s，无颤音）的包络起伏 | — | 见下 |
| 440 Hz 处的次谐波 | 145 Hz，280 ms | 无 |
| 367 Hz 处的次谐波 | 90 Hz，140 ms | 无 |
| 67→69 过渡的包络 | 塌到 44% | 10% 以内 |

**改法**（`voxsample.js`）：
1. 窗长只跟**输出周期**走：`g = 2 × op`，叠加和恒等于 1，不再需要补增益。
2. **每一粒吸附到 ±半个源周期内的真实正峰**：误差不再累积，取粒点等于钉在波形上。

#### 3）病因 B：转音的每一步短于耳朵的音高分辨下限

转音的形状是 `[1,0]` / `[-1,2,1,0]`，尾巴最长 0.34 s，四音绕圈时每个音只有 **0.085 s**。
人耳要把一段声音听成"一个音高"大约需要 50–100 ms（这段时间内听觉系统在做周期积分）；
0.085 s 低于下限，听到的不是"一个音"，是"抖了一下"，夹在两个正常音之间就很扎耳朵。

**改法**（`score.js` 人声段的转音块）：
- 尾巴上限 0.34 → **0.48 s**，切成两段，每段 **0.21–0.24 s**；
- **四音绕圈整类取消**（需要 4×0.20 = 0.8 s，做不到）；
- 概率 32% → **15%**，且只给 ≥0.95 s 的长音。

| | 改前 | 改后 |
|---|---|---|
| 黎明海面 转音音数 | 42（0.085 s ×25、0.17 s ×17） | **8**（0.24 s） |
| 夜之城 / 森林 | 14 / — | 2 / 4（0.21–0.22 s） |

#### 4）改后

`?selftest=1&short=1&n=3`：`nan=0`、`peak=0.695/0.829/0.872`、`WAV ok=true`、0 条 console error。
人声段 20 s 的"短促音高事件"从 18 处（含两处 100–280 ms 的次谐波）降到 16 处，
且全部是 25–60 ms 的**分析端倍频误判**（自相关在转折点上锁到了 2 倍或 4 倍周期），不是音频里的东西。

**参数位置**：窗长与相位吸附在 `voxsample.js` 的 `voxPsola`（`g`、`snapR`）；
转音步长与概率在 `score.js` 人声段末尾的转音块（`tail`、`shape`、`r < 0.15`）。

**配套工具**（本轮新增，`tools/svs/`）：
- `probe_range.js <wav> <起> <止>`：逐 20 ms 打印音量/音高/周期度，看"短音"的形状；
- `f0_blips.js <wav>`：全曲扫"短促音高事件"（持续 <200 ms 的偏离）；
- `find_blips.js <wav>`：全曲扫"短促能量突起"（找咔哒声/爆音）。

**已知取舍**：转音变慢变稀之后，"灵动感"会略降。如果以后觉得平，
正确的做法是加**别的**手段（乐句末的渐弱、换气口、句首的滑入），**不是把转音改回 0.085 s** ——
那个时长在物理上就不可能被听成一个音。
